# iOS toolchain notes preserved from customer-app-redesign

**Date preserved:** 2026-09-09  
**Source branch:** `customer-app-redesign`  
**Status:** reference only — not accepted runtime configuration

The source redesign branch contained Xcode/CocoaPods/Flutter-generated project changes alongside the UI work. They were intentionally not copied into the audited UI integration because they were generated under a different Flutter/Xcode state and were not independently validated as an iOS release task.

Useful observations to revisit during the dedicated App Store/iOS release task:

- the source branch raised the CocoaPods platform declaration from the old/default iOS 12 baseline to iOS 15;
- it regenerated CocoaPods workspace/project references and `Podfile.lock`;
- it adopted the newer Flutter implicit-engine/scene-delegate project shape;
- it added Xcode scheme preparation/LLDB settings generated by a newer Flutter toolchain;
- it regenerated the complete iOS AppIcon asset set from the new AIDA app icon.

The **app icon assets themselves are accepted UI/branding work and are included** in the audited integration.

The generated Xcode/CocoaPods changes must be recreated from current `master` using the supported Flutter/Xcode toolchain during the App Store readiness task rather than copied blindly from the old branch.

Recommended future procedure:

```text
current master
  -> supported Flutter
  -> current Xcode / iOS SDK
  -> flutter pub get
  -> pod install / Flutter project migration
  -> inspect generated diff
  -> flutter analyze/test
  -> archive/IPA
  -> physical iPhone + TestFlight validation
```

This document preserves the useful migration evidence without making stale generated project files authoritative.
