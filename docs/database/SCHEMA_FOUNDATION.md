## TASK-AUTH-001 changes

Public signup provisioning now has explicit trusted behavior:

- profile application role is always `customer`;
- display name is copied from signup metadata only as profile data;
- `is_student` is an untrusted declaration;
- standard signup creates `standard/not_submitted` membership;
- student declaration creates `student/pending` membership;
- member code is always generated by `public.generate_member_code()`;
- client-supplied role/member-code/verified-status claims do not control persisted trusted fields.

Profile/member SELECT policy now permits own rows or admin/owner bulk reads. Ordinary staff do not receive a bulk directory through these tables.

`public.list_admin_members()` returns member/profile directory fields for authenticated admin/owner callers. It is `SECURITY INVOKER`, has no anon execute privilege and remains subject to forced RLS.
